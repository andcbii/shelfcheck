# Refresh needed TMDB episode crosswalks on a new UTC day

TMDB can add or correct a TVDB episode's external ID without reporting the show in its change feed. Saved TMDB external-ID crosswalk responses were reused until a forced refresh or a provider-change invalidation, so a valid empty answer could keep an owned episode in missing results indefinitely.

Each saved provider relationship records the time its response was actually received. When a live scan reaches the TMDB external-ID crosswalk for a TVDB episode (lookup by TVDB episode ID), it reuses a saved response only if that response was received on or after the scan's starting UTC date; otherwise, including responses saved before receipt times were recorded, it requests the crosswalk again. Matches and valid empty responses are treated alike. A response received after midnight during a scan is current for that scan and for later scans on its receipt date.

The check is lazy and per episode: only crosswalks that normal matching actually reaches are refreshed, so earlier coverage avoids the request and an unused old response creates neither a request nor a Coverage Issue. There is no midnight job and no bulk refresh of undated responses. Reuse, offline cached rechecks and restarts never renew a receipt time, and receipt dates are never inferred from catalogue downloads.

When a required refresh fails, by a provider or transport failure or an unreadable successful response, the expired response is rejected: it grants no coverage; existing episode-scoped failure handling, same-day retries and Coverage Issues apply. The rejection is durable. A failed request leaves no saved response, and an unreadable payload is saved without a receipt time only so offline rechecks can explain the failure. When a failed live scan retains the show's last-good comparison (for example because a provider catalogue download failed), that scan's TMDB crosswalk outcomes still replace the retained evidence: rejected responses are removed and responses received during the scan replace older ones. Offline Manual Match rechecks, before or after a restart, therefore make no requests, renew nothing and cannot revive a rejected response; independent evidence such as a complete-set Manual Match still covers the episode, without resolving the failed check. A fresh valid empty response replaces the old answer and withdraws only the coverage it established.

Separate show comparisons that need the same lookup share it as shared crosswalk evidence, keyed by the TVDB episode and kept across restarts. A live scan reads the shared outcome, not the comparison's own saved copy: an ordinary lookup reuses a usable shared response received on or after the scan's starting UTC date, and otherwise requests it; overlapping comparisons wait for the one request already in flight and receive its result or failure. Each comparison still saves its own copy, with the original receipt time, for offline rechecks, which replay that copy unless the shared outcome is a later rejection, so a failure seen by one show stops every other show's offline recheck from granting coverage from the rejected answer. Sharing never renews a receipt time and never shares ownership: every comparison matches the response against current library inventory. Forced lookups (a single-show rescan, provider-change invalidation, or a retry of the show's own failed crosswalk) bypass same-day reuse and accept only a response requested during that scan; their outcome replaces or rejects the shared evidence, so later ordinary comparisons cannot fall back to an invalidated copy. Clearing one show's cache removes the shared evidence for the lookups that show had saved, so the next scan requests them; clearing the whole cache removes all of it. Failed lookups are not shared beyond the in-flight request: a comparison that reaches a rejected lookup after the request ended retries it.

This augments ADR-0003 rather than reopening it: provider catalogue download timestamps, age limits, same-day catalogue reuse, change-feed verification and the fifth-scan safeguard are unchanged, as are IMDb and Trakt crosswalk reuse, explicit cache clearing, single-show rescans and provider-change invalidation, which still bypass same-day reuse. ADR-0001 Manual Match coverage is unchanged.
