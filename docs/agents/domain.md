# Domain docs

## Before exploring

Read the root `GLOSSARY.md` and any decisions in `docs/adr/` relevant
to the area being explored.

If these files are absent, proceed silently. Create glossary entries
and ADRs through domain-modeling when terms or decisions are resolved.

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md`: domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider the terminology or note
the gap for domain-modeling.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR,
including the reason for reopening that decision.
